1//! # scrapfly-sdk
2//!
3//! Async Rust client for the Scrapfly API. See the crate-level
4//! [`Client`] and the `examples/` directory for usage.
5//!
6//! ```no_run
7//! use scrapfly_sdk::{Client, ScrapeConfig};
8//!
9//! # async fn run() -> Result<(), scrapfly_sdk::ScrapflyError> {
10//! let client = Client::builder().api_key("scp-...").build()?;
11//! let result = client
12//!     .scrape(&ScrapeConfig::builder("https://httpbin.dev/html").build()?)
13//!     .await?;
14//! println!("{}", result.result.status_code);
15//! # Ok(()) }
16//! ```
17//!
18//! ## Unblocker
19//!
20//! The anti-bot bypass is turned on with `unblocker`, on both
21//! [`ScrapeConfig`] and [`CrawlerConfig`]:
22//!
23//! ```no_run
24//! # use scrapfly_sdk::ScrapeConfig;
25//! # fn run() -> Result<(), scrapfly_sdk::ScrapflyError> {
26//! let cfg = ScrapeConfig::builder("https://example.com")
27//!     .unblocker(true)
28//!     .build()?;
29//! # Ok(()) }
30//! ```
31//!
32//! `asp` is the previous name. Its builder methods are deprecated aliases
33//! that keep working; when both names are supplied `asp` wins, in either call
34//! order, and the two are never OR-ed. On the built structs the value lives in
35//! a single field still called `asp` (renaming a public field would break
36//! existing callers); `unblocker_enabled()` reads it and `set_unblocker()`
37//! writes it. The request still carries the parameter as `asp` on the wire —
38//! a server-compatibility detail of this release.
39//!
40//! The error variant [`ScrapflyError::AspBypassFailed`] keeps its name: it is
41//! dispatched from the literal `ERR::ASP::*` codes the API returns, and
42//! customer `match` arms name it.
